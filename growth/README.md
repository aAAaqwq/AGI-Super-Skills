# Evidence-backed growth playbooks

These playbooks turn repository evidence into human-reviewed outreach. They do not authorize automated posting, bulk messaging, vote manipulation, fabricated testimonials, undisclosed promotion, or collection of private data.

## Operating gates

| Gate | Exit evidence |
|---|---|
| G0 — Safety and ownership | Named human owner, approved accounts, platform rules reviewed, stop authority assigned |
| G1 — Repository truth | Validator green; setup and claims checked against the target `main` revision |
| G2 — MVTA | Minimum Viable Trusted Artifact is reproducible, bounded, and independently reviewed |
| G3 — Audience fit | One audience/problem hypothesis supported by interviews, issues, or observed demand |
| G4 — Draft review | Claim ledger, links, disclosure, accessibility, and manual-post checklist approved |
| G5 — Small release | One human-posted experiment per community; replies handled manually and respectfully |
| G6 — Learn or stop | Results logged, qualitative feedback summarized, harms checked, next decision recorded |

Do not skip a gate because a calendar date arrived. A failed gate means fix, narrow, or stop.

## MVTA definition

The Minimum Viable Trusted Artifact is the smallest artifact that lets a new user reproduce one useful outcome from a clean environment. It includes a pinned revision, safe preview, explicit apply step, expected output, limitations, recovery, and verification evidence.

For this repository, a suitable MVTA is a starter-kit preview and isolated apply walkthrough—not a catalog-size claim, autonomous company demo, live trade, or automatic social post.
