# X playbook

Use X for small, attributable learning loops. All posting and replies are manual and human-reviewed.

## Before drafting

1. Confirm G0–G3 and choose one audience problem.
2. Link one MVTA or exact repository path on `main`.
3. Check every factual claim in [`evidence-and-feedback.md`](./evidence-and-feedback.md).
4. Avoid exact catalog counts unless the validator is green and the revision is recorded.

## Useful formats

- Build note: problem, design choice, tradeoff, reproducible command, limitation.
- Safe-start demo: preview output, `--apply` boundary, expected files, recovery.
- Learning note: what user feedback changed, with no invented quote or identity.
- Release note: material behavior change and verification evidence.

## Review checklist

- The first line states a user problem, not hype.
- Claims link to code, tests, or a reproducible artifact.
- Codex native package, manifests, and generic starter kits are not conflated.
- No guaranteed outcome, financial performance, affiliation, or production-readiness claim.
- Image alt text and a plain-text explanation are included when needed.
- An authorized human edits, posts, watches replies, and can delete or correct it.

## Cadence and conduct

Start with at most one original project post per week. Do not use bots, engagement pods, mass mentions, unsolicited DMs, quote-post pile-ons, or repeated replies. Acknowledge criticism and correct errors in the original thread.
