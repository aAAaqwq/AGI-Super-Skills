# 故障响应 — Incident Response

## 元信息
- **触发条件**: 系统健康巡检异常 / Agent 报告 / 用户反馈
- **执行频率**: 按需
- **预计耗时**: 视严重程度 15-120 分钟
- **负责 Agent**: COO（指挥）+ PE（修复）

## 执行步骤

### Phase 1: 检测与定性 (0-5 min)
```
🚨 故障报告
编号: INC-[YYYY]-[NNN]
时间: YYYY-MM-DD HH:MM
级别: P0/P1/P2
现象: [具体症状]
影响: [哪些功能/用户受影响]
```

### Phase 2: 止损 (5-30 min)
- **P0**: 先回滚/降级，后查因
- **P1**: 尝试快速修复，不行则降级
- 优先级: 恢复服务 > 保护数据 > 定位根因

### Phase 3: 根因分析 (15-60 min)
使用 5-Whys 方法：
```
现象: [出了什么问题]
Why 1: [为什么]
Why 2: [为什么]
Why 3: [为什么]
Why 4: [为什么]
Root Cause: [根本原因]
```

### Phase 4: 修复与预防
1. 实施修复
2. 添加监控告警（防止同类问题）
3. 更新 SOP/文档

## 输出
- 故障报告 → `memory/incidents/inc-YYYY-NNN.md`
- 修复 PR → PE
- 预防措施 → COO 跟踪
