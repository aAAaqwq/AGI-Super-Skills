# 性能剖析 — Performance Profiling

## 元信息
- **触发条件**: 用户反馈延迟 / 监控告警 / 定期优化
- **执行频率**: 按需（至少每月 1 次）
- **预计耗时**: 1-2 小时
- **负责 Agent**: PE

## 执行步骤

### Step 1: 定义基准 (10 min)
```
## 性能基准

| 指标 | 当前值 | 目标值 | 测量方法 |
|------|--------|--------|----------|
| API 响应 P50 | 230ms | < 200ms | curl -w |
| API 响应 P99 | 1.2s | < 500ms | 压测 |
| 内存使用 | 450MB | < 500MB | /proc |
| 启动时间 | 8s | < 5s | time |
```

### Step 2: Profiling (20-60 min)
1. **CPU 热点**: 找到最耗 CPU 的函数
2. **内存分析**: 找到内存泄漏/大量分配
3. **I/O 瓶颈**: 磁盘/网络 I/O 等待
4. **并发分析**: 锁竞争/线程阻塞

### Step 3: 优化实施 (20-40 min)
按 ROI 排序优化：
```
| 优化项 | 预期提升 | 修复成本 | ROI |
|--------|----------|----------|-----|
| [具体优化] | X% | Xh | 高 |
```

**优化顺序:**
1. 算法/数据结构优化（最高 ROI）
2. 缓存（重复计算 → 缓存）
3. 并发（串行 → 并行）
4. I/O（批量 → 减少调用）
5. 语言层（编译优化/JIT）

### Step 4: 验证 (10 min)
- 对比优化前后基准
- 确认无功能回归
- 更新基准文档

## 原则
- **先 Profile 再优化** — 不猜测瓶颈
- **量化验证** — 优化前后必须有数据对比
- **不过度优化** — 达到目标值就停

## 输出
- 性能报告 → CEO
- 优化 PR → 代码库
