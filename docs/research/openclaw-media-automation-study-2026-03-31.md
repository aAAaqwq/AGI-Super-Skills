# OpenClaw 自媒体自动化运营学习纪要（2026-03-31）

## 来源
昨晚通过 10 轮一次性 cron 学习任务产出，主题为 **OpenClaw 自媒体自动化运营**。

## 一句话结论
昨晚真正学到的不是“怎么自动发内容”，而是：**把自媒体运营从手工作坊，升级成可复制、可迭代、可放大的内容系统。**

---

## 10 轮核心结论（压缩版）

### 1. 内容工厂总链路
- 整体要看成一条流水线：**选题 → 内容生成 → 封面生成 → 多平台入草稿 → 次日复盘**。
- 真正卡效率的通常不是“写不出来”，而是中间某一环掉链子，导致全链路断掉。
- Daniel 只做 3 步：**选题、审稿、确认发布**；其余应尽量自动化。
- 选题层要做成**批量供稿系统**，不是临时想灵感。

### 2. 小红书 SOP
- 选题先从“用户卡在哪”出发，而不是“我想写什么”。
- 标题不是摘要，是点击钩子；每篇至少并行 5 个候选，再筛 2 个。
- 正文要写成“可抄作业的过程”，不是说明书。
- XHS 完整链路应模块化：**选题池 → 标题 5 选 2 → 正文定稿 → 封面双版本 → 标签组装 → 自动入草稿**。

### 3. 公众号自动化链路
- 最稳的链路是：**深度选题 → 长文生成 → 微信 HTML 排版 → 封面生成 → 草稿箱提交**。
- 公众号不是口播稿平台，适合 2000-3000 字“深度但不学术”的内容。
- Markdown 只是上游，**微信 HTML 才是真正交付物**。
- 草稿箱是默认安全出口，发布前必须截图确认。

### 4. 抖音自动化限制与风控
- 登录态不能只看 cookie 文件存在，要做真实登录检测。
- 图文发布至少 2 张图，别拿 1 张图测图文链路。
- 上传最大坑往往是**超时**，不是 selector。
- 草稿按钮真实文案目前更常见是 **“暂存离开”**，不是“存草稿”。
- 最优改造方向：加一层 `auth-check -> ui-doctor -> upload -> draft` 预检层。

### 5. 登录态管理体系
- 当前真实问题不是平台不够多，而是**配置和资产不一致**。
- 小红书这类强风控平台，优先级应该是：
  **existing session > 可见真实浏览器登录 > 二维码截图 > 短信登录兜底**。
- CDP 的正确定位是：**附着已登录浏览器**，不是默认启动新浏览器。
- 登录态维护应以 **完整 Chrome profile** 为核心，不只是 cookies。
- 后续应建立统一的 **auth registry（单一真相源）**。

### 6. 封面与配图方法论
- `content-cover-gen` 负责“图讲什么”，`content-typography` 负责“字怎么排”，`content-illustration-strategy` 负责“正文该插什么证据图”。
- 正确顺序：**先定主判断 → 找视觉隐喻 → 压标题分行 → 再决定正文证据图**。
- 封面负责让人点进来，正文配图负责让人相信你。
- 平台模板不能混用：小红书/抖音偏强刺激，公众号/掘金偏编辑秩序感。

### 7. 选题系统
- 选题系统先从**信号源**出发，不从灵感出发。
- 每日热点要同时过 3 个筛子：
  1. 是否匹配 Daniel 人设
  2. 是否能拆 2-3 个角度
  3. 是否适合多平台复用
- 标题评分建议量化成 4 维：**相关性 / 信息密度 / 情绪张力 / 差异化**。
- 内容池要分成：**热点型 / 常青型 / 转化型** 三池并行。

### 8. 多平台适配
- 要拆成两层：
  - **共性模块**：选题、原稿、标题、封面、标签、排期、数据回流
  - **平台适配器**：标题规则、正文结构、素材规格、发布方式
- 不能一稿平推；要先做一份**母稿**，再裁成 XHS / GZH / Douyin / Juejin / ZSXQ 版本。
- API 平台和浏览器自动化平台要区别对待，不要硬抹平。

### 9. Cron + Skill 体系设计
- 原则：**cron = when，skill = how，workspace/config = what**。
- 长 SOP 不要塞进 cron，cron 只放最小触发信息。
- Skill 要按稳定职责拆，不要按今天的流程图拆。
- 最小 cron payload 只传：**任务 ID / 场景名 / 输入引用**。
- 平台自动化要把**内容生产**与**发布执行**彻底解耦。

### 10. 总复盘：核心方法论
1. 先搭系统，别先堆内容
2. 人只抓 3 个关键节点
3. 平台不是复制，是适配
4. 先做“可发到草稿箱”，再做“全自动发布”
5. 爆款不是玄学，是模板化生产
6. 内容团队要模块化，不要混成一团
7. 自动化的核心是低摩擦交接
8. 先追求稳定日产，再追求单篇爆款
9. 数据复盘必须反哺前端创作
10. 所有高频动作都要文档化、脚本化、可复用

## 我的判断（结合现状）
你现在最缺的不是“更多模型”或“更多平台脚本”，而是：
- 一个统一的**内容中台视图**
- 一个统一的**登录态真相源**
- 一个统一的**单平台闭环验证标准**

先把这 3 个补齐，后面的自媒体自动化才会从“能跑一次”，升级成“能稳定跑很多次”。
