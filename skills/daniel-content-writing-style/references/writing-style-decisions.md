# A.A 写作风格决策记录

## 一、逐题确认结果

1. **读者第一感受：A**
   “这个人真的亲手做了，我也能照着试。”真实执行与可复刻性优先；趣味促进追更，专业由证据体现。

2. **情绪暴露：B**
   适度写真实的犹豫、惊喜、失望、自嘲和释然；情绪用于解释判断，不写成个人日记。

3. **幽默来源：B**
   使用真实翻车、认知反差和轻微自嘲；不使用高密度网络梗，不编造段子。

4. **观点锋利度：B**
   明确表达个人判断，同时给证据、推理、适用条件和边界；不做资料堆砌，也不无证据制造争议。

5. **技术细节：A，经追问选 A**
   正文不铺代码，使用人话、截图和操作顺序；复刻所需命令、提示词和参数集中到文末“一键复制区”。

6. **开头钩子：B→A 融合**
   先说读者正在经历的使用痛点，再立即给出真实结果或意外；前 3—5 句建立相关性、真实性和反差。

7. **正文推进：C**
   使用关键时间线与问题模块的混合结构。每个转折回答：发生了什么、证据在哪、为什么、你怎么做。

8. **截图策略：最终选择真实截图方案**
   裁出关键区域并脱敏，再加一句人话标注。拒绝重绘假终端和无法核验的美化卡片。

9. **段落节奏：B**
   以 1—3 句短段落为主，关键结论单独成段；避免碎片化营销体。

10. **读者关系：A 为主，B 为辅**
    “我做给你看”为主，“我们一起研究”为辅；不摆老师或成功导师姿态。

11. **结尾 CTA：C，经追问选 B**
    偏好强而单一的 CTA；核心草案只确认读者动作、交付资产及资产是否就绪，具体是评论关键词、收藏、关注、链接还是不设 CTA，由平台专家决定。任何领取承诺都必须已有真实可交付资产。

12. **长度与平台：用户提出平台优先工作流**
    不设统一字数。先确认平台无关核心草案，再做平台原生适配。

13. **平台生产：B**
    一次只完成一个主平台版本，每轮恰好调用一个专业 Subagent；若该角色不可用就停止，不由主 Agent 冒充平台专家。

14. **核心草案所有权：A**
    主 Agent 单独负责核心草案；平台 Subagent 只做适配，主 Agent 回审，用户最终批准。

15. **最终人格：B**
    年轻、好奇、亲自折腾，偶尔自嘲，关键处判断坚定。

## 二、对标分析如何转化

现有对标资料覆盖九位创作者。A.A 不复制任何单一账号，而是组合其可迁移能力：

| 对标 | 借鉴能力 | 不照搬 |
|---|---|---|
| 何同学 | 年轻好奇、人物目标、失败与情绪 | 昂贵制作、固定语气和人设 |
| 林亦 | 结果先行、视觉实验、真实意外形成笑点 | 夸张表演、视觉替代证据 |
| 蔚蓝 Weilanx | “正在做”的 Build in Public | 成熟结果包装和身份组合 |
| 宝玉 xp | 来源、解释、证据与克制判断 | 只做翻译摘要、缺少自身经历 |
| 空格的键盘 | 将实验沉淀为 Agent/Skill 资产 | Skill 数量崇拜、只展示界面 |
| 半撇老师 | 痛点、步骤、资产与 CTA 承接 | 强营销承诺、过早课程化 |
| 花叔 Alchain | 作品证据、异常结果、机制解释 | 成熟创业者或顾问权威姿态 |
| 数字生命卡兹克 | 好奇、亲测、热点与个人判断 | 无证据恐慌和追热点 |
| 老麦的工具库 | 结果展示与低门槛包装 | “最强、躺赚、神器”等膨胀表达 |

A.A 的组合应为：

> 何同学的年轻好奇 × 林亦的可见实验 × 蔚蓝的正在构建 × 宝玉的证据纪律 × 空格的资产化 × 半撇的可执行路径。

花叔、卡兹克和老麦主要用于选题与包装参考，不作为 A.A 的语言人格模板。

## 三、平台原生适配原则

平台适配不是机械改变字数，而是重新组织用户意图、入口和消费方式：

- **小红书**：先确认封面与首屏，正文短、层次清楚、适量 Emoji，真实图片承担证明与收藏价值。
- **微信公众号**：长文完整说明因果与证据，用图片打断阅读疲劳，文末承接可复用资产。
- **抖音**：把核心草案重写为前几秒钩子、口播、镜头、字幕和素材清单；用户确认后再进入外部视频生成/剪辑。
- **B站**：强化人物目标、过程转折、结果展示、完播和系列关注。
- **X/Twitter**：压缩成明确判断、证据和可对话的短帖或线程。
- **知乎**：围绕具体问题、搜索意图、完整解释和可信来源组织。

平台偏好可能变化。实际制作时应由对应专业 Subagent 基于当前平台情况适配；不得把本记录中的长度、Emoji 或格式描述当作永久算法规则。

## 四、发布前风格自检

- 素材是否真实且可追溯？
- 开头是否先说痛点，再给真实结果或意外？
- 是否只保留改变判断的关键转折？
- 每个转折是否有证据、人话解释和读者动作？
- 是否出现了真实个人判断和适度真实情绪？
- 小白能否读懂，准备动手时能否在文末直接复制？
- 截图是否是真实现场，且完成裁剪、脱敏和人话标注？
- CTA 是否只有一个，且承诺的资产已经可交付？
- 核心草案是否先经用户确认？
- 平台版本是否调用了专业 Subagent，并由主 Agent 回审？
