# 运营节奏与价值流

设计能稳定交付价值、尽早暴露异常并持续改进的运行系统。优化端到端流动，不追求每个局部都满负荷。

## 输入

先确认：

- 已批准的目标、优先级、非目标和验收结果；
- 需求入口、终端客户、交付单位与时间期望；
- 现有步骤、负责人、依赖、工具和决策点；
- 当前产能、在制品、等待、返工与失败数据；
- 高风险动作、人工审批点和可接受中断范围。

若战略目标尚未确认，退回 CEO；若专业方案尚未确定，交对应领域负责人。

## 设计流程

### 1. 定义价值单位

写清一次完整交付给谁带来什么结果、从何时开始、以什么证据结束。不要把任务关闭、文档创建或会议完成当作终端价值。

### 2. 描绘当前价值流

按实际发生顺序记录每一步的输入、输出、负责人、处理时间、等待时间、依赖和返工原因。区分：

- 产生价值的工作；
- 保证质量或安全的必要控制；
- 等待、重复录入、无主交接和无效审批。

先找限制整体吞吐的瓶颈，不平均优化所有步骤。

### 3. 设计责任接口

每个结果只设一位直接负责人。每次交接明确：

- 输入何时算完整；
- 输出按什么标准接收；
- 谁能作操作决定；
- 多久未响应必须升级；
- 拒收、返工和范围变化如何记录。

### 4. 配置产能与节奏

根据瓶颈产能限制在制品，保留应对异常的余量。仅设置能触发决定的节奏，例如：

- 短周期：承诺、阻塞和立即决策；
- 周期复查：吞吐、周期、返工、积压和风险；
- 阶段复盘：目标结果、容量变化、流程增删和资源建议。

取消没有明确输入、决定或输出的例会。

### 5. 设计异常与恢复

对关键失败写明：发现信号、影响范围、第一响应者、限制影响动作、人工接管、升级阈值、恢复标准、回退方式和证据保存。事件中先保护客户与系统，稳定后再分析促成条件。

### 6. 通过运营门

进入常态运行前，确认：

- 目标、价值单位和完成证据一致；
- 关键路径与瓶颈基于现状证据，而非流程图想象；
- 每个接口有唯一负责人和最晚升级点；
- 产能假设、在制品上限与优先级规则明确；
- 高风险步骤有人类审批，失败可停止、接管和回退；
- 指标有定义、来源、时间窗、阈值和对应动作。

自动化还需额外证明规则稳定、异常分类足够、人工接管可用、维护责任明确、预期收益高于持续成本。

## 停止与升级

- 目标或优先级互相冲突：暂停建模，交 CEO 决断。
- 专业方案、风险口径或验收条件不清：交对应负责人补齐。
- 真实产能未知：先短期测量，不承诺虚假期限。
- 涉及外部消息、资金、凭证、生产变更或不可逆影响：停止在执行前，取得人类明确批准。
- 没有可观察回执时，不声称定时、监控、通知或自动化已经运行。

## 相邻角色边界

- CEO 提供已确认的方向、优先级和资源边界。
- COO 使用本 Skill 设计运行系统并报告执行现实。
- CTO、CPO、CFO、CLO 等角色保留专业方案和事实判断。
- Governor 独立复核完成证据；运营设计者只提供材料，不决定 Gate。
