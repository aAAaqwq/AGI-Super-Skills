## 一、核心定位

- 产品定位：每4小时运行一次的 Binance 合约投机雷达，不自动下单。
- 时间窗口：每轮分析最近24小时的 Binance Square 高质量帖子与新闻。
- 标的范围：覆盖帖子涉及的全部币种；只有存在有效合约交易对的币才能输出合约交易计划，其他币只作为新闻或情绪上下文。
- 核心输出：当前有机会的币、方向、Entry、SL、TP1/TP2、当前价格、失效条件、评分和证据。
- 无机会时：必须明确输出“无合格机会/等待”，不得为了凑数生成交易建议。
- 每轮输出上限：TOP 3 可执行机会 + 最多5个观察标的。
- 不输出：仓位比例、账户风险比例、固定杠杆或自动交易指令。

## 二、调度与交付

- 调度时区：UTC。
- 固定运行时间：`00:00、04:00、08:00、12:00、16:00、20:00 UTC`。
- 每轮都发送报告，包括没有机会的轮次，用于区分“无机会”和“系统未运行”。
- Telegram 目标：`8518085684`，只发送精简雷达结果。
- 本地保存：完整帖子、作者评分、K线数据、推导证据、报告和运行记录。
- 首次失败：10分钟后自动重试一次。
- 重试成功：只记录恢复，不额外打扰。
- 重试仍失败：Telegram 告警并标注故障阶段（Chrome、抓取、行情 API、分析或消息推送）。
- 成功数据不得被失败结果覆盖；下游失败时不得提交去重状态，下轮继续重试。

> 当前事实：截至本决策记录创建时，没有在 OpenClaw 活动任务、macOS crontab 或 LaunchAgent 中发现已启用的币安四小时定时任务。以上是已确认目标调度，并非已上线声明。

## 三、信息来源与抓取通道

采用双通道：

1. **专业作者 Profile 通道**
   - 直接抓取 Tier A/B 作者主页最近24小时的全部帖子。
   - 这是交易信号的主要来源，避免依赖广场推荐算法导致重点作者漏抓。
2. **广场发现通道**
   - 扫描 Binance Square 主页、交易员排行榜和新闻流。
   - 用于发现新作者、新币、突发信息和市场共识。

### 来源分级

- Binance 官方公告、Binance Research、Square Official：官方来源。
- 普通 Binance Square 作者内容：标记为“广场消息/第三方观点”，不能因为托管在 Binance 就视为已核实。
- 不要求逐条去外部新闻站交叉验证；普通作者新闻只有在价格、成交量、多作者共识或官方内容支持时，才能提高交易评分。

## 四、交易员发现与作者分层

### 每日排行榜发现

- 每日执行一次交易员候选池更新，不必每4小时重复发现作者。
- 当前从 Binance Futures Smart Money 公共入口抓取已真实观测的30D榜单：
  - 实盘盈利额（`PNL`）；
  - 收益率（`ROI`）。
- 成交量与胜率保留为页面未来提供时的扩展目标，不属于当前 Smart Money Web UI 的已验证能力。
- 每个已支持榜单抓 TOP 30；榜内与跨榜先按 `topTraderId` 去重。只有存在显式来源证据时才映射到 Square `squareUid`，不能把两个ID视为同一字段。
- 预计形成约50–100名候选作者，再进入实盘、时长、受众和内容质量筛选。

### 作者证据

作者评级不能只看粉丝或点赞，综合：

- 是否公开合约实盘；
- 实盘交易时长；
- 30D盈利、收益率、成交量和胜率排名；
- 收益持续性，而非单次暴利；
- 粉丝、点赞、徽章和账号年龄；
- 帖子是否有方向、逻辑、Entry、SL、TP和失效条件；
- 是否持续设置止损、是否滥用极端杠杆；
- 本系统前向追踪的胜率、平均R值、MFE、MAE和可执行率；
- 广告、拉群、佣金导流和情绪喊单比例；
- 帖子观点与公开实盘仓位是否一致。

### 硬准入规则

- Tier A 顶尖作者至少拥有一个“合约实盘或30D交易榜单”标签，并持续发布详细分析。
- 粉丝、点赞和普通徽章只用于同级排序，不能单独把作者评为顶尖。
- 公开实盘和实盘交易时长属于硬指标。

### 交易时长分层

- Tier A：公开实盘交易 ≥1年。
- Tier B：3–12个月，进入观察池。
- Tier C：不足3个月，只作弱情绪参考。

### 外部认证观察期

- 有强排行榜与实盘标签、但本系统尚未积累20条信号的作者，标记为 `Tier A·外部认证观察期`。
- 可以优先抓取和进入候选，但作者可信度最高暂时只能得 `20/25`。
- 累计至少20条已触发信号后，按真实结果升级为正式 Tier A 或降级。
- 报告必须区分“Binance标签证明”和“本系统历史验证”。

### 种子作者证据合同

- Profile展示名、粉丝数、点赞、徽章、持仓标签与路由username都只是可变观察字段。
- 稳定 Square 作者主键必须使用 `squareUid`；Smart Money 的 `topTraderId` 是另一命名空间，除非存在双ID显式证据，否则不得映射。
- 测试包只包含合成种子身份；真实作者资料与动态排行榜响应不随公共 Skill 发布。
- 同次历史证据只确认 Binance 官方 `top-traders` 小程序的 `30D PNL` 参数，桌面端未渲染完整TOP30；该阶段的 `0/4 PARTIAL_SEED_DISCOVERY` 仅是旧口径，不再代表当前 Smart Money 接入状态。
- 2026-08-01 源项目曾从官方 `https://www.binance.com/zh-CN/smart-money` 对应公共只读接口取得 `PNL/ROI` 三页各10行，覆盖为 `2/2 COMPLETE`。动态响应不随本 Skill 发布；`VOLUME/WIN_RATE` 未被当前 UI 观测，禁止按旧四榜合同补造响应。
- 该证据含60个唯一 `topTraderId` 和60/60公开交易员详情，但 `topTraderId ≠ squareUid`；没有显式映射就不能拉取对应 Square 内容、给作者表现加分或晋级 Tier A。
- ROI榜的小额本金高倍收益不能单独证明可复制性、持续性或风险质量；仍须通过公开实盘时长、内容质量、前向样本与60天证据门。
- 任一种子作者都必须重新通过“持续详细分析”门；仅有共享实盘、标签或排名时，作者分不得上调。

## 五、作者评分的时间口径

- 原始帖子、K线快照、报告和错误日志：保留60天。
- 作者聚合统计与晋级/降级历史：长期保留，不必长期保存帖子全文。
- 同时维护：
  - 最近60天滚动评分；
  - 长期累计评分。
- 最终作者等级：`最近60天表现 × 70% + 长期累计表现 × 30%`。

## 六、帖子质量规则

- 详细分析优先：包含方向、依据、市场结构、Entry、SL、TP和失效条件。
- Tier A 作者的简短 Entry/SL/TP 帖可以进入候选，但作者内容分不能拿满，必须由系统独立完成多周期、布林带、成交量、ATR和RR验证。
- Tier B/C 或陌生作者的简短信号只能观察或过滤。
- 只有情绪和方向、没有参数也没有分析的内容直接过滤。
- 广告、拉群、推荐码、无依据“100x/月球”喊单直接降权或丢弃。

## 七、行情数据与技术框架

### API 优先级

- 优先使用 Binance 合约公开行情 API。
- 合约 API 临时失败时可使用现货 API 作为价格代理，但报告必须标注“Spot Proxy”。
- 不得将现货代理数据伪装成合约标记价或合约成交数据。

### 多周期

- `15m`：精确入场与短期触发。
- `1h`：局部趋势、成交量、支撑阻力。
- `4h`：主要结构和交易方向。
- `1d`：大级别位置与极端追涨杀跌风险。

### 联合推导体系

`专业作者/新闻 → 多周期结构 → 布林带 → 成交量 → ATR止损 → RR验收`

- 首版布林带参数：`BB(20,2)`。
- 使用 `%B` 和 `BandWidth` 区分贴轨趋势、波动挤压和假突破。
- 触碰上轨不自动做空，触碰下轨不自动做多。
- 强趋势贴轨按延续处理；Squeeze 必须等待方向突破和量价确认。
- ATR负责止损缓冲，布林带不能单独替代止损。

## 八、帖子参数与系统推导的优先级

1. 作者原 Entry 尚未错过、SL/TP 尚未触发、4h结构仍成立：采用作者参数。
2. 已离开原入场区，但作者方向与逻辑仍被当前K线支持：推导“当前二次入场计划”，并明确标记为系统推导。
3. 已触发SL、已到主要TP或4h结构被破坏：帖子失效，不再推荐。
4. 禁止复制已经过时的点位。

作者没有完整参数时，由系统结合帖子逻辑和K线推导：

- Entry：15m/1h回踩确认区或突破回测区，不直接追当前价格。
- SL：交易逻辑失效位置之外，加约 `0.3–0.5 ATR` 缓冲。
- TP1：最近主要支撑、阻力或流动性位置。
- TP2：4h级别下一目标位。
- TP1最低RR：`1.5`。
- 主要目标最低RR：`2.0`。
- 无法同时满足结构止损和最低RR时输出“等待”，不生成计划。

## 九、机会评分与输出门槛

100分模型：

| 维度 | 分值 |
|---|---:|
| 作者可信度 | 25 |
| 帖子分析完整度 | 15 |
| 帖子时效性 | 10 |
| 15m/1h/4h/1d趋势一致性 | 20 |
| 布林带、成交量和突破确认 | 10 |
| SL合理性与盈亏比 | 15 |
| 新闻级别或多作者共识 | 5 |

门槛：

- `≥75`：TOP 3 候选。
- `65–74`：观察标的。
- `<65`：过滤。
- 即使总分达标，只要合约不存在、信号失效或最低RR不合格，直接淘汰。

## 十、信号结果追踪

- 入场区在发布后24小时内未触及：`未触发`，不算亏损。
- 入场触发后继续追踪72小时，或采用作者明确持仓周期。
- 先触发SL：失败。
- 先触发TP1：初步成功；继续记录TP2。
- 同一根K线同时覆盖SL和TP：保守记为先触发SL。
- 记录实际R值、MFE、MAE和信号可执行率。
- 未触发与过期信号不进入胜率，但单独计入可执行率统计。

## 十一、报告必须包含

- 最新抓取时间：UTC + 本地时间。
- 最近24小时帖子总数、有效数、新增数、重复数。
- Tier A/B作者抓取覆盖率和作者身份来源。
- TOP 3：币种、方向、Entry、SL、TP1/TP2、现价、失效条件、总分和主要证据。
- 最多5个观察标的及等待条件。
- 被过滤的主要原因。
- 无机会时明确“等待/无合格机会”。
- 完整本地快照路径。

### 同币多空冲突裁决

- 同一轮报告不得同时把同一币种列为做多和做空机会。
- 按币种聚合过去24小时的多方与空方帖子，分别计算来源加权证据分。
- 只有某一方向总分达到75分，并且领先反方向至少10分，才可进入TOP 3候选。
- 最终方向还必须通过当前1h/4h结构、成交量、布林带和信号时效校验。
- 满足输出条件时，报告须披露存在的反方向高质量观点及主要反对证据。
- 多空分差不足10分、结构混乱或任一市场硬门槛不通过时，降级为观察标的或直接过滤。
- 当前市场结构和信号失效条件具有否决权；作者名气、粉丝数或历史排名不得覆盖市场数据否决。

### TOP 3相关性处理

- TOP 3不因币种间相关性或同方向市场Beta而降级、替换或重新排序。
- 候选机会继续完全按照既定100分模型和硬门槛排序。
- 多个入选币种高度相关、同属一个叙事板块或明显受BTC同方向驱动时，报告必须标注“集中风险”。
- 集中风险提示只用于披露，不加入机会分，也不提供仓位、杠杆或账户风险建议。
