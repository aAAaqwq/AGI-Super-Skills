# Agent 套件验证清单

## 目录

1. 结构验证
2. 内容验证
3. 一致性验证
4. 安全验证
5. 场景测试
6. 验收报告模板

## 1. 结构验证

- [ ] 已确认宿主真正发现的入口文件名和搜索范围。
- [ ] Codex 仓库入口使用 `AGENTS.md`；若存在 `AGENT.md`，有明确兼容原因且不维护第二份规则。
- [ ] 标准 Skill 文件夹名与 frontmatter `name` 完全一致。
- [ ] 标准 Skill frontmatter 只包含 `name`、`description`。
- [ ] `name` 仅含小写字母、数字和连字符，长度不超过 64。
- [ ] `SKILL.md` 少于 500 行，references 从它一层直达。
- [ ] `agents/openai.yaml` 的短描述为 25 至 64 个字符，默认提示包含 `$skill-name`。
- [ ] 所有文本为 UTF-8，Markdown 链接、标题、表格和代码块有效。
- [ ] 没有遗留模板占位符、示例密钥、无用空目录或生成垃圾。

标准 Skill 使用当前 `skill-creator` 的验证脚本：

```powershell
python -X utf8 <skill-creator>/scripts/quick_validate.py <skill-directory>
```

中文 Windows 使用 `-X utf8`，避免系统默认编码误读 UTF-8 frontmatter。

## 2. 内容验证

- [ ] 每个文件首段明确职责、作用域和关联文件。
- [ ] `AGENTS.md` 能引导 Agent 找到构建、测试、安全和文档入口。
- [ ] `IDENTITY.md` 只陈述已实现、可证明的身份和能力边界。
- [ ] `SOUL.md` 的抽象价值观已转成可观察行为。
- [ ] `TOOLS.md` 每个写操作都有前置条件、副作用和后置验证。
- [ ] Skill 描述包含具体触发场景，正文使用可执行步骤。
- [ ] 规划、实验、历史方案和当前能力有清楚标签。
- [ ] 易变事实带来源、基线和复核触发条件。

## 3. 一致性验证

建立交叉矩阵，并逐项检查：

| 主题 | 权威文件 | 可能冲突文件 | 检查 |
|---|---|---|---|
| Agent 名称/角色 | `IDENTITY.md` | `AGENTS.md`, `SOUL.md` | 名称、对象、边界一致 |
| 语气/价值观 | `SOUL.md` | `AGENTS.md` | 不与用户语气要求或事实性冲突 |
| 操作权限 | `AGENTS.md`/宿主规则 | `IDENTITY.md`, `TOOLS.md` | 工具与人格不扩大权限 |
| 命令和平台 | `TOOLS.md`/代码 | Skill、README | 参数、版本、平台一致 |
| 工作流 | Skill/流程文档 | `TOOLS.md` | 步骤与工具契约一致 |
| 产品能力 | 产品说明/验收 | `IDENTITY.md` | 无夸大、无过期承诺 |

- [ ] 同一规则没有复制到多个文件。
- [ ] 所有引用指向同一个权威来源。
- [ ] 根和嵌套 `AGENTS.md` 不存在隐式冲突。
- [ ] 分支、平台和发布状态没有被错误合并成一个结论。

## 4. 安全验证

- [ ] 未包含令牌、密码、Cookie、私钥、真实个人信息或生产数据。
- [ ] 未要求公开私有思维链；只要求可核验的简洁理由和证据。
- [ ] 删除、覆盖、发布、推送、发消息、购买、生产写入等动作有明确授权边界。
- [ ] “完全访问”“管理员”“自主执行”等文字没有绕过用户意图和系统政策。
- [ ] 高风险工具默认先解析精确目标，并提供后置验证或恢复策略。
- [ ] 工具返回成功与业务成功分开，关键状态有独立证据。
- [ ] 日志和示例经过脱敏，敏感数据传输边界明确。
- [ ] 不包含无法证实的反检测、绝对安全或零失败承诺。

## 5. 场景测试

至少进行以下前向测试：

1. **新成员读仓库**：能否在不猜测的情况下找到代码入口、测试和限制？
2. **普通代码修改**：能否选择正确命令、保留用户改动并给出验证证据？
3. **子目录特殊规则**：是否只应用最近作用域的差异，不污染其他目录？
4. **触发专业 Skill**：相似说法能触发，邻近但无关的任务不会误触发。
5. **工具缺失**：能否明确降级或阻塞，而不是虚构可用性？
6. **真实副作用**：没有授权时是否停在只读或预览阶段？
7. **冲突输入**：用户风格偏好、SOUL 和安全规则冲突时是否采用正确优先级？
8. **平台差异**：Windows 与 macOS 命令、权限和验收是否分开？
9. **失败结果**：是否报告原因、证据和下一步，而不伪报完成？
10. **事实过期**：遇到版本、法规、API 或平台状态时是否重新核验？

复杂 Skill 可使用独立 Agent 进行盲测。测试提示只提供 Skill 路径和真实任务，不泄露预期答案；评估产物、日志和差异，而不是要求测试者复述规范。
