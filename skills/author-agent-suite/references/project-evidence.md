# 本项目 Agent 套件证据与提炼结论

## 审计基线

- 通用基线：`origin/main@401ad9c`。
- Windows 基线：`codex/win-native-uia-1.1.7@526abba`。
- 审计日期：2026-07-27。
- 两个基线中的根 `AGENTS.md`、`SKILL.md`、`SOUL.md`、`TOOLS.md`、`IDENTITY.md` 内容哈希一致，因此人格和操作入口没有平台分叉。

## 读取的项目材料

| 文件 | 当前承担的职责 | 可迁移经验 |
|---|---|---|
| `AGENTS.md` | 面向用户的行为层、引导路径、交互铁律 | 行为层可以把价值观转成具体场景，但仓库编辑规则与产品运营话术宜进一步分层 |
| `IDENTITY.md` | “伯乐”名称、CHRO 数字助手定位、服务对象、能力底座 | 身份文件应回答“是谁、为谁、边界是什么” |
| `SOUL.md` | 性格、信念、表达方式和禁忌 | 用可观察行为解释人格，比只列形容词更可执行 |
| `TOOLS.md` | 文档优先级、常用命令、参数语义和定时前提 | 工具速查需要同时保留参数语义和运行前提 |
| 根 `SKILL.md` | 项目概览、测试流程、意图到脚本映射、文档路由 | 项目手册能承担总入口，但没有标准 Skill frontmatter 时不能当作可安装 Skill |
| `docs/agent架构.md` | Agent 层与项目架构说明 | 套件应链接架构事实，不在多个入口复制实现细节 |
| `docs/权限架构.md` | 账号与权限边界 | 权限事实应高于人格偏好，并保持可验证 |
| `docs/分支与跨平台发布管理.md` | 分支、平台和版本管理 | 平台事实必须带分支与版本基线，不能把实验分支当主线能力 |

## 发现的问题模式

1. **文件存在不等于自动加载。** 当前项目通过 `TOOLS.md` 和文内链接建立阅读顺序，但 `IDENTITY.md`、`SOUL.md`、`TOOLS.md` 本身不是通用自动发现协议。通用规范必须要求验证宿主加载机制。
2. **根 `SKILL.md` 与标准 Skill 同名但不同构。** 当前根文件没有 YAML frontmatter，是项目操作手册；`docs/deposit/*/SKILL.md` 才遵守标准技能结构。新套件必须显式区分这两类文档。
3. **行为层与仓库操作层可能混写。** 当前 `AGENTS.md` 重点是如何引导招聘用户，适合产品 Agent；面向代码 Agent 时还需补充编辑、测试、工作树和安全规则，或把产品行为移到单独参考后由入口路由。
4. **能力文案会随平台迁移过期。** 根身份和工具文件仍以 macOS cua-driver 为主要叙述，而 Windows 分支已转向原生 UIA/Win32/CDP。跨平台能力必须指向带基线的事实文档。
5. **绝对性安全或检测声明风险高。** “检测不出来”“绝不会”等表达需要被真实测试范围和失败边界替代；通用规范要求只陈述证据支持的结论。
6. **业务交互规则不能替代授权。** “主动给下一步”适合用户体验，但真实打招呼、发消息、标记候选人或发布版本仍须服从更高层副作用授权。

## 对本 Skill 的影响

- 采用 `AGENTS.md` 为权威入口，单数 `AGENT.md` 只提供宿主兼容模板。
- 将详细文件规范、加载架构、验收清单拆成一层 references，保持主 `SKILL.md` 精简。
- 提供可复制 starter kit，但要求先替换占位符并完成事实审计。
- 把“命令返回成功”和“业务状态已验证”分开，作为 `TOOLS.md` 的强制字段。
- 将分支、平台、权限、外部写操作和个人数据列为套件级复核门禁。
